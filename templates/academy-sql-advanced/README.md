# academy-sql-advanced

This project is the companion workspace for **Run the Pipeline**, the advanced course in
SQL in the Age of AI. It arrives as a complete, deterministic retail pipeline: your job is
to operate it, test it, break it, fix it, and harden it with your coding agent.

The first run is intentionally not clean: `bruin validate` passes, while `bruin run` fails
on `churn_risk` because lesson 12 investigates that asset. Stop on any different error.

## Setup

Install Git and Bruin, then run the setup prompt in [`course/README.md`](course/README.md).
The default path is local DuckDB and needs no credentials. It creates `academy.duckdb`.
The optional `cloud` environment uses MotherDuck when `MOTHERDUCK_TOKEN` is configured.

```text
academy-sql-advanced/
├── AGENTS.md
├── course/                  # syllabus, progress, quizzes, rubrics and capstone key
├── docs/                    # schema, contracts and operational reference
├── pipeline/
│   ├── pipeline.yml
│   └── assets/               # generate → staging → core → mart
└── queries/                  # reconciliation and operations worksheets
```

The eight source tables are generated by SQL assets. No data files are shipped. The
generators use fixed dates and integer arithmetic, so fresh runs produce identical data.
They include late ingestion, store-local timestamps, partial UTC timestamps, DST edges,
customer snapshots, source defects, and one inert prompt-shaped customer value.

`customer_snapshots` is a partial monthly snapshot of 30 changing customers. The
`dim_customer_history` asset is a runnable stub: lesson 7 turns it into `scd2_by_time`,
and its first real SCD2 run requires `--full-refresh`. The snapshot data includes both
overlapping and gapped validity windows for the exercise.

The course is taught by your own agent. Say `next lesson` to begin, and `review my work`
after each task. The other controls are `where am I`, `repeat`, `hint`, and `skip`.
